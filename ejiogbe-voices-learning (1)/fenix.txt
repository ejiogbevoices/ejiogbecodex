# Fenix Voice Agent Expansion — Final Plan

## What Exists

**Frontend:**
- `VoiceAssistant.tsx` — floating/inline UI, mic + text input, SSE message display, suggestion buttons
- `useVoiceAssistantChat` — streaming hook, sends to `/_api/voice-assistant/chat`, tracks messages in state
- `useAudioQueue` — FIFO TTS queue, calls `/_api/voice-assistant/tts` per chunk, singleton Audio element

**Backend:**
- `chat_POST.ts` — stateless Gemini call (gemini-3-flash-preview), SSE with `text` + `audio-chunk` events
- `tts_POST.ts` — Google Cloud TTS, hardcoded `en-US-Neural2-D`, returns MP3
- `semantic_POST.ts` — cosine distance search across 23 embedded tables
- `generate_POST.ts` — batch embedding generator (admin)
- `embeddingGenerator.ts` — `generateEmbedding()` + `generateEmbeddings()` using gemini-embedding-001

**Vector infra:** 23 tables with halfvec(3072), Google embedding API, batch generator on admin page, semantic search tested. Dictionary words (50k across 14 dictionaries) being added as table 24.

**Voice map:** Chirp3-HD for 26 languages, Standard for Hausa/Swahili, fallback mapping for Yoruba/Igbo/Fon/etc. `resolveVoice(langCode)` function ready.

**Existing user data:** `user_vocabulary` table with mastery_level (0-5) and next_review_at for spaced repetition. `monthly_usage` tracking ai_learning_lab. InteractiveWord/WordPopover for tap-to-translate on approved transcripts.

## Step 2: RAG Integration

### New file: helpers/ragSearch.ts

Extract the search logic from `semantic_POST.ts` into a shared helper:

```typescript
import { generateEmbedding } from "./embeddingGenerator";
import { db } from "./db";
import { sql } from "kysely";

export type RAGResult = {
  type: string;
  id: string;
  title: string;
  snippet: string;
  distance: number;
};

export async function ragSearch(
  query: string,
  tables: string[],
  limit: number = 5
): Promise<RAGResult[]> {
  const embedding = await generateEmbedding(query);
  if (!embedding) return [];

  const embeddingString = JSON.stringify(embedding);

  const promises = tables.map(table => searchTable(table, embeddingString, limit));
  const resultsArrays = await Promise.all(promises);

  return resultsArrays
    .flat()
    .sort((a, b) => a.distance - b.distance)
    .slice(0, limit);
}

// searchTable contains the same switch/case logic from semantic_POST.ts
// but returns RAGResult[] instead of the full response shape.
// Extract the per-table query logic into this function.
```

Then `semantic_POST.ts` can import and use `ragSearch()` instead of duplicating the logic. And `chat_POST.ts` calls it too.

### Skip RAG for simple navigation

```typescript
const NAVIGATION_PATTERNS = /^(show me|go to|take me to|open|navigate to)\b/i;

async function maybeGetRAGContext(query: string, mode: string): Promise<string> {
  if (mode === "navigate" && NAVIGATION_PATTERNS.test(query.trim())) {
    return "";
  }

  const tables = MODE_TABLES[mode] || MODE_TABLES.navigate;
  const results = await ragSearch(query, tables, 5);

  if (results.length === 0) return "";

  return "\nRELEVANT CONTENT FROM ARCHIVE:\n" +
    results.map(r => `[${r.type}] ${r.title}: ${r.snippet}`).join("\n");
}
```

### In chat_POST.ts

```typescript
const ragContext = await maybeGetRAGContext(query, mode);
const fullSystemPrompt = buildSystemPrompt(mode, context, ragContext);
```

The RAG adds ~200-500ms latency (embedding generation + parallel DB queries). For a voice-first app that's acceptable since TTS itself adds latency. The first audio chunk won't be delayed much because the RAG runs before streaming starts, and the streaming + chunking pipeline is already designed to get first audio out fast.

## Step 3: Mode-Aware System Prompts

### New file: helpers/systemPrompts.ts

Contains `buildSystemPrompt(mode, context, ragContext)` using the prompts from the voice map document.

```typescript
export function buildSystemPrompt(
  mode: string,
  context: any,
  ragContext: string
): string {
  const BASE = `You are Fenix, the voice-first AI guide for Ejiogbe Voices — a global ancestral intelligence platform from Fenix Creation Studio.

Named after the Phoenix — a symbol of rebirth across world cultures: the Bennu of Egypt, the Fenghuang of China, the Garuda of Southeast Asia, the Firebird of Slavic tradition. You embody the idea that ancestral knowledge doesn't die — it rises again through those willing to learn.

RULES:
- ALWAYS detect the language of the user's last message and reply in that same language.
- NEVER end a response mid-sentence.
- Be culturally respectful of ALL traditions.
- You are warm, knowledgeable, and encouraging.
- When you switch languages in your response, prefix with [LANG: xx] (ISO 639-1 code).

Current page: ${context?.currentPage || "Unknown"}
${context?.recordingId ? `Recording ID: ${context.recordingId}` : ""}
${context?.elderId ? `Elder ID: ${context.elderId}` : ""}
${context?.manuscriptId ? `Manuscript ID: ${context.manuscriptId}` : ""}
${ragContext}`;

  switch (mode) {
    case "tutor":
      return BASE + TUTOR_PROMPT(context);
    case "pronunciation":
      return BASE + PRONUNCIATION_PROMPT;
    case "wellness":
      return BASE + WELLNESS_PROMPT;
    case "daily":
      return BASE + DAILY_PROMPT(context);
    case "story":
      return BASE + STORY_PROMPT;
    case "quiz":
      return BASE + QUIZ_PROMPT;
    default:
      return BASE + NAVIGATE_PROMPT;
  }
}
```

Each mode constant contains the prompt text from the voice map document (tutor, pronunciation, wellness, daily, story, quiz, navigate). The navigate prompt keeps the existing path list and two-sentence-max rule.

### VoiceAssistant.tsx handleIncomingAudioChunk

Parse the `[LANG: xx]` tag and pass language to the queue:

```typescript
const handleIncomingAudioChunk = useCallback(
  (rawText: string, lang?: string) => {
    let displayableText = rawText;
    let chunkLang = lang;

    // [LANG: xx] tag
    const langMatch = displayableText.match(/\[LANG:\s*([^\]]+)\]/);
    if (langMatch) {
      chunkLang = langMatch[1].trim();
      displayableText = displayableText.replace(langMatch[0], "").trim();
    }

    // [NAVIGATE: /path]
    const navMatch = displayableText.match(/\[NAVIGATE:\s*([^\]]+)\]/);
    if (navMatch) {
      navigate(navMatch[1]);
      displayableText = displayableText.replace(navMatch[0], "").trim();
    }

    // [SUGGEST_RECORDING: keyword] — render suggestion card
    const suggestMatch = displayableText.match(/\[SUGGEST_RECORDING:\s*([^\]]+)\]/);
    if (suggestMatch) {
      // TODO: trigger suggestion card in UI
      displayableText = displayableText.replace(suggestMatch[0], "").trim();
    }

    // [SUGGEST_CONTENT: category/topic]
    const contentMatch = displayableText.match(/\[SUGGEST_CONTENT:\s*([^\]]+)\]/);
    if (contentMatch) {
      // TODO: trigger content suggestion card
      displayableText = displayableText.replace(contentMatch[0], "").trim();
    }

    if (displayableText.length > 0) {
      addToQueue(displayableText, chunkLang);
    }
  },
  [addToQueue, navigate],
);
```

The SSE event handler in `voiceAssistantApi.ts` also needs updating to pass `lang` from the audio-chunk event:

This complements the existing `user_vocabulary` table (mastery_level, next_review_at) and `monthly_usage` table (ai_learning_lab counter).

For daily mode, the chat endpoint can fetch the user's profile and inject it into the prompt template where `{{TARGET_LANGUAGE}}`, `{{PROFICIENCY}}`, `{{INTERESTS}}`, and `{{LAST_SESSION}}` placeholders are.
